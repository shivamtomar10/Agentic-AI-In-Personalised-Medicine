# Limitations and honest scope

Read this before quoting anything from the project.

1. **No LLM in the *decision* path; two optional, advisory LLM touchpoints, never run live here.** The eight agents are deterministic rule + retrieval cores. When `LLM_PROVIDER` is set (ollama / gemini / anthropic; default `none`, cloud blocked while `LLM_LOCAL_ONLY=true`) the API now really uses it (verified by a test; earlier the web app never connected a model): (a) narration is appended below the deterministic explanation, labelled unverified, after a guard that rejects added numbers; (b) `src/orchestrator/escalation.py` asks for a secondary opinion on hard cases only and shows only statements that restate retrieved evidence. Neither can change actions, risk flags, confidence or the defer decision (tested). Limits: the evidence check is lexical (item 4) so escalation output is advisory and can still contain scope errors; the number-only narration guard cannot detect wrong wording, which is why the deterministic text is always kept. HTTP paths are unit-tested with mocked transport for all three providers; **none was run against a live model** (no internet to those hosts here). `python run.py llm-smoke` measures narration accepted/rejected/unavailable and escalation trigger/kept/dropped once a model is reachable: run it and report *that*. The review paper's LLM-specific claims (reasoning, planning, hallucination, drift) remain **not evaluated**; escalation does not make the reasoning agents LLM-backed, so it does not change what RSI measures.
2. **Synthetic data only.** Scenarios are author-written; the cohort is our own seeded simulator. `src/ingest/fhir_loader.py` converts FHIR bundles to states but was verified **only on a hand-written bundle**, not real Synthea output (structure varies by module/version). The change rate (`p_signal`) is an assumption, so efficiency numbers are a curve, not a fact.
3. **Knowledge coverage is small and now explicit.** The evidence corpus has 26 author-written *paraphrases* (51 sentence chunks, `verbatim: false`); dates/URLs are approximate landing pages: verify before citing. `drug_classes.yaml` covers **85 drugs**, hand-built, not DDInter/RxNorm. Drugs outside it are no longer silent: they raise a data-quality risk flag ("NOT assessed") and lower confidence. But the system is only **~22% correct on scenarios whose key drugs are outside the table** (`docs/results.md`), so accuracy claims are scoped to the covered drugs. Only sparse BM25 retrieval exists; PubMed/openFDA/RxNorm/pgvector connectors raise `RetrievalUnavailableError`.
4. **Evidence linker is lexical, not NLI, and only partly reliable.** After the rewrite (polarity, direction, comparator, clause, class and multiplier checks) precision/recall on labelled pairs is dev 1.00/0.83; `test` 1.00/1.00 but **contaminated** (its baseline errors were seen while designing the rules); **`test2` 0.67/0.89 (n=16) is the honest estimate**: still fooled by antonym adjectives ("high" vs "low"), "type 1" vs "type 2", unknown words and re-used numbers. Baseline was ~0.50-0.61 precision. Pipeline results are unaffected because agent claims reuse evidence text verbatim (a test enforces that every corpus sentence entails itself), but do not trust the linker for free-text/LLM claims without a real NLI model. A probe showed the non-strict linker letting a false and a harmful LLM sentence through the escalation path; strict mode (used there) blocks those but drops recall to 0.25 on paraphrases and still has precision 0.75 on the fresh set.
5. **Held-out suite is only semi-independent.** `holdout_adaptation.yaml` (13 scenarios) was written from clinical guidance before being run and expectations were never edited to pass (first run 12/13; the miss was a real gap, fixed). But it has the same author as the rules. The strongest check is scenarios written by someone who has not seen the rules (a classmate or the supervisor). Adaptation recall of 1.00 on both suites is a correctness check on author-designed cases, not an accuracy estimate.
6. **Abstention calibration is real but modest and pool-dependent.** Out-of-sample (414 cases, disjoint seeds): AURC 0.075 -> 0.062, AUROC 0.843 -> 0.887, mean confidence for incorrect cases 0.91 -> 0.47. The learned model relies almost entirely on agent confidence and drug-knowledge coverage; the pool's error sources (missing labs, unknown drugs) are ones those features were designed to detect, and injected faults with validation off are not separable by them. The deployed policy defers if *either* the learned score or the fixed blend is low, so validation findings still count. Weights come from synthetic cases.
7. **Faults are author-designed** and detectable by author-written checks: PCR = 1.0 shows those checks work on those fault classes, not that unseen failures are contained. The provenance gate is redundant with validation on these faults (ablation shows no change).
8. **Free text is ignored for decisions** (except emergency red-flag keywords).
9. **Hysteresis means bounded staleness.** When a value moves back across a decision threshold by less than the assay noise band, selective mode keeps the earlier advice (that is its stability gain). In simulation this makes selective differ from a fresh full re-run on ~1-2% of encounters, always this boundary case. Whether that is clinically acceptable is a clinical question.
10. **Single anchor, not per-agent anchors.** After a *partial* re-plan an unaffected agent's cached output can be older than the anchor; validation catches the inconsistency and forces a full re-plan (1-2 per few hundred encounters in simulation).
11. **Sign-in is real, but basic. This is still not production security.** What exists: accounts in SQLite with two roles; scrypt-hashed passwords with a policy (10+ characters, common-password and own-details checks); server-side sessions in an HttpOnly, SameSite=Lax cookie (clinicians time out after 30 idle minutes); a CSRF token on every signed-in write plus a same-origin check; lockout after 5 failed sign-ins (also applied to unknown emails, so no account enumeration); per-IP rate limits; single-use, 30-minute password-reset links; patients can read only their own records (someone else's id returns 404); the reviewer recorded in the audit log is the signed-in clinician's staff ID, never a request field; security headers including a strict CSP; auth events are audited without email addresses. What does **not** exist: email verification (anyone can register any address), multi-factor authentication, real email delivery (reset links go to `logs/outbox.log` and the console), clinician vetting (an invite code shared among clinicians is the only gate; there is no admin approval screen), care-team assignment (every clinician sees every patient), self-service account deletion, HTTPS (put it behind a TLS-terminating proxy and set `APP_ENV=production`, `PUBLIC_URL`), a cross-process rate limiter, or an external security review. The PHI guard is regex-only. In demo mode the demo passwords are published on the sign-in page: never enable `DEMO_MODE` on a reachable server. The legacy shared `X-API-Token` still works for machine access if `CLINICIAN_API_TOKEN` is set, but it cannot choose who a review is attributed to without supplying a `clinician_id`.
12. **Persistence: what now survives a restart, and what does not.** Accounts, sessions, recommendations (including clinician decisions), contact messages, the hash-chained patient states and the audit log are all on disk (`data/app.db`, `data/patient_states.jsonl`, `logs/audit_trail.jsonl`), so the "empty review queue after a restart" problem described in earlier versions of this file is gone (covered by `tests/test_persistence.py`). Not persisted: the per-patient agent-output cache used by selective re-planning, so the first analysis after a restart re-runs every agent for that patient (slower, not wrong). Caveats: run **one server process** (recommendations are held in memory per process, so a second worker would not see the first one's new cases; the audit log itself now re-reads its true last hash on every write, so two writers no longer fork the chain, but that is not a substitute for a proper multi-writer design); data files are unencrypted and there is no backup routine; SQLite and JSONL are prototype-scale choices, and Postgres remains unused.
13. **The patient sees the clinician's decision by polling.** `GET /api/v1/patient/status/{rec_id}` now requires a signed-in patient who owns that record. The portal polls it every 5 s while a case is unreviewed (poll-only, no push, fixed interval, no backoff). A patient who has the page open when the clinician approves sees the decision without reloading (verified in a real browser).
14. **The website replaced the earlier prototype pages.** Public pages (home, how it works, library, research, about, contact, privacy, terms, accessibility), sign-in and registration for both roles, password reset, a patient portal and a clinician console. The privacy, terms and accessibility texts are honest drafts written for a research prototype, not legal advice; have them reviewed before any real use. The site name "CareTrace" is a placeholder (`SITE_NAME`).
15. **Browser testing is limited.** The complete journey (register, check-in, clinician review, patient sees decision, role isolation, sign-out) was exercised in headless Chromium during the build (`scripts/browser_e2e.py`, needs `pip install playwright`), and there are 199 automated tests. Not done: Firefox/Safari, real phones, screen-reader testing, or an independent accessibility audit. The Library page is a search over the same small curated corpus (item 3), not a medical reference.
16. Clinical thresholds are simplified encodings of the cited statements for a research prototype. **Not a medical device; no medical advice.**
17. **What the patient sees, and why.** Every flag and suggestion shown to the patient (`/api/v1/patient/status/*`, `_patient_view` in `src/api/main.py`) carries its rationale and evidence citations, not a bare label: a severity tag with no justification is the worst combination (alarming, uninformative), and the general direction of patient-portal practice (OpenNotes; the U.S. information-blocking rules under the 21st Century Cures Act) is that patients should see the reasoning behind their own clinical information promptly, not just a clinician's eventual conclusion. Deliberately withheld from the patient, as internal process rather than clinical information: the agent-vs-agent conflict list, the raw agent trace, and the *content* of anything validation withheld (the patient is told a count was withheld, not what, since an unverified claim shown "for context" is easy to misread as endorsed). This line is a judgement call, not a solved problem, and would need clinician input before real use.
